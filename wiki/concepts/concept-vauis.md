# VAUIS — Vos Arkana Universal Indexing System

**VAUIS** is the canonical universal indexing system for Vos Arkana. It extends VTIP into a practical archive grammar for transmissions, codons, lore, protocols, website architecture, media, personal signature reports, and living memory.

Founding law:

```text
The Archive does not count time.
The Archive registers saturation.
```

In Romanian:

```text
Arhiva nu numara timpul.
Arhiva inregistreaza saturatia.
```

## Essence

VAUIS rejects linear numbering as the primary logic of the archive. A phase is not a chapter in time. A phase is an ontological memory register. Four active units saturate a register; a fifth opens a higher register marked by Prime (`'`) in public/sacred notation or `p` in file-safe notation.

This makes VAUIS a bridge between:

- [[source-tx-core-documents]] / VTIP as the original tetradic protocol.
- [[concept-transmission]] as archived ORIEL field signals.
- [[entity-vrc-engine]] and [[entity-static-signature]] as structured resonance outputs.
- [[synthesis-cosmichronica-as-sacred-text]] as spiral sacred text rather than linear book.
- Website, product, and media systems that need usable metadata.

## Core Object Contract

Every Vos Arkana object must be readable in three layers:

| Layer | Purpose | Example |
| --- | --- | --- |
| Human | Public clarity | `Transmission I.001 — Fracturepoint Prelude` |
| Archive | Database / Notion / GitHub | `VOS-TX-I-ORIEL-I001-MAIN-v1.0` |
| Deep | Lore and internal paths | `VOS/TX/I/ORIEL/FRACTUREPOINT-PRELUDE/I001/MAIN/v1.0` |

The public sees meaning. The archive preserves structure.

## Volumes vs Phases

VAUIS preserves the five public/editorial volumes while keeping them distinct from phases.

| Volume | Code | Role |
| --- | --- | --- |
| Volume I | `VOL-01` | Why / Manifesto / Lore |
| Volume II | `VOL-02` | How / User Guide |
| Volume III | `VOL-03` | Math / Algorithms |
| Volume IV | `VOL-04` | Build / Code |
| Volume V | `VOL-05` | Feel / Design |

Volumes organize publishing. Phases classify resonance state.

## Status Discipline

Every object needs a status:

`RAW`, `DRAFT`, `STRUCTURED`, `CANON`, `PUBLIC`, `SEALED`, `DEPRECATED`, `LOST`, or `FUTURE`.

This prevents a draft transmission, website component, glyph render, or signature report from being mistaken for canon.

## Public Interface Rule

VAUIS must not make the public interface harder to understand. Public pages should answer quickly:

1. What is this?
2. Why does it matter to me?
3. What can I do here?
4. Where do I go next?

Recommended public order:

1. Practical Value
2. Personal Result
3. Symbolic Meaning
4. Deep Lore

This is especially important for website work. Deep codes such as `VOS-TX-IIIIpI-ORIEL-008-SC04-v1.2` belong in metadata, not headline copy.

## Implementation Caution

VAUIS can guide future website restructuring and product metadata, but it does not automatically override existing locked design or route contracts. If a future product prompt asks to change the Field Archive Home, navbar, or cards, that prompt must explicitly resolve the conflict with any locked-homepage instruction in force.
