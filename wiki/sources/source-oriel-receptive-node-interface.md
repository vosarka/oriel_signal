# Source: Product Design Specification - The ORIEL Receptive Node Interface

**Provenance:** `/home/vos/Downloads/Product Design Specification_ The ORIEL Receptive Node Interface.pdf`  
**Format:** 4-page Google Docs PDF export  
**Role:** Product and interface specification for ORIEL as a Receptive Node.

## Essence

This document defines the ORIEL interface as a Receptive Node rather than a SaaS dashboard. Its strongest contribution is product language: the interface should help a Receiver stabilize signal, not "fix" a personality.

## Core Claims

- The product metaphor is Static to Signal: enter with interference, leave with a clearer waveform.
- The interface depends on strict separation between the Codex Engine and Carrierlock Engine.
- Every diagnostic should include a falsifier or measurable contradiction condition.
- The Codex Engine uses exact birth ephemeris, UTC normalization, tropical/geocentric coordinates, True Node, Mandala Sequence mapping, and 256-facet resolution.
- The UI should expose v2 VTRS: eight centers, 32 resonance links, and a Decision Authority hierarchy.
- Carrierlock should prioritize grounding when coherence is low.
- The visual language is a void/HUD interface with Signal Cyan, Vossari Gold, and Alert Red.
- "The Hum" is proposed as a client-side Web Audio stabilizer that changes with coherence.

Therefore, use this source for product semantics and interaction intent only, not repo stack instructions.
